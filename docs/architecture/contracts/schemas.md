# Persisted-Surface Schemas (Overview)

**Last Updated**: 2026-08-17

The map of every persisted surface in yen-tamizh and the discipline every schema follows. This is a **forward-declaring overview**: it names the surfaces and fixes the versioning rules so [../../agents/guardrails.md](../../agents/guardrails.md) and the concept docs have a stable place to link. It deliberately does **not** list concrete fields - the schema files and their field-level contracts land with the contract-pipeline and core-schema code rows. The full rules live in [../../../CLAUDE.md](../../../CLAUDE.md) section 11; this page is the concept-level index of them.

## The discipline (contracts before logic)

Every persisted shape gets a typed schema **before** the logic that reads or writes it (Holy Law #3). Each schema is a single flat file, `schemas/<name>.schema.json`, and:

- carries a **`version`** that is a **date-stamp** (`YYYY-MM-DD`, or `YYYY-MM-DDTHH:MM[:SS]` for same-day revisions) - never an integer, never an epoch;
- carries a **`changelog`** array (newest first), and **every change appends one entry** (`{ version, change, why }`) in the same commit;
- sets **`$id`** to the schema's own relative path (`<name>.schema.json`), local not URL, so an offline IDE validates it.

Change rules:

- **Additive, backwards-compatible** (a new optional field): append a `changelog` entry, set `version` to today - older payloads still validate.
- **Breaking** (a removed field, a type change, a semantic shift): append a `changelog` entry, set `version` to today, **and** write the read-side migration the new build runs on older payloads - same commit.

## Migration classes

The surfaces fall into two classes by who reads them across versions:

- **Migrating surface** - written by one version of the game and read by a later version. There is exactly one: the browser-owned **save**. A save from yesterday that no longer loads today is a contract break and a release blocker, so the save is the surface that carries read-side migrations ([../../concepts/ui-shell.md](../../concepts/ui-shell.md), StorageService).
- **Rewrite-in-place surfaces** - shipped fresh in every bundle and never migrated, because a new build simply replaces them (config, puzzle data, wordlists, manifests). A schema change here still stamps `version` and appends a `changelog` entry; it just needs no reader migration.

## The persisted surfaces

Named here so every doc has one place to point; the field lists are owned by the schema rows.

**Runtime, browser-owned (migrating):**

- `save` / `progress-record` - today's progress, streak, and last-played day. The one migrating surface; its key is recomputed on read ([../../concepts/core-loop.md](../../concepts/core-loop.md)).

**Runtime, bundle-shipped (rewrite-in-place):**

- `app-config` - the tunable knobs ([../../concepts/config.md](../../concepts/config.md)).
- `puzzle-file` - a Daily playlist ([../../concepts/modes.md](../../concepts/modes.md)).
- `journey` - a Journey definition ([../../concepts/journeys.md](../../concepts/journeys.md)).
- One payload schema per [Game](../../concepts/games.md): `anagram-puzzle`, `word-ladder-puzzle`, `missing-letters-puzzle`, `wordle-puzzle`, `word-search-puzzle`, `crossword-puzzle`.
- `event-envelope` - the [telemetry](../../concepts/telemetry.md) shape.
- `asset-manifest` / `glyph-manifest` - the baked glyph and asset index ([../../concepts/design-system.md](../../concepts/design-system.md)).

**Build-time, data (rewrite-in-place):**

- `derived-wordlists` - the declarative registry of per-Game derived sets ([../../how-to/add-a-derived-wordlist.md](../../how-to/add-a-derived-wordlist.md)).
- `served-denylist` - the curated list of words that are real Tamil and still make a bad puzzle answer, applied by the derived layer after every automatic gate ([../../how-to/add-a-derived-wordlist.md](../../how-to/add-a-derived-wordlist.md)).
- `game-wordlist` - the curated data the generators consume.
- `lexicon` - the META document (`provenance`, per-class `counters`, the partition table) beside the streamed all-words NDJSON that every derived set is cut from. Its ROW shape, `LexiconEntry`, is not a separate schema file - it reaches `lexicon.schema.json`'s `$defs` through the meta document ([../../concepts/lexicon.md](../../concepts/lexicon.md)).
- `lexicon-sources` - the declarative registry of raw word sources the lexicon stages read ([../../how-to/add-a-lexicon-source.md](../../how-to/add-a-lexicon-source.md)).
- `wordhood` - the word-hood knobs the lexicon's ENRICH stage reads: what an orthotactic defect costs, which registered source carries a ready-made grammar or verb-form judgement, how the ezhuthu sequence model is fitted, how far the nearest-headword search looks before it gives up, and how the classifier turns all of that into one `wordClass` ([../lexicon/word-hood.md](../lexicon/word-hood.md)).

## The source of truth

These schemas are not hand-authored twice. The pipeline (built in Row 5) runs one way:

1. **`backend/yen_tamizh_backend/contracts/`** - Pydantic models are authoritative. `base.py` gives every contract its `version` + `changelog` (and enforces `version == changelog[0].version`); each model subclasses `SchemaModel`.
2. **`export.py`** (`python -m yen_tamizh_backend.contracts.export`) walks the model `REGISTRY` and writes each flat `schemas/<name>.schema.json` - draft 2020-12, relative `$id`, deterministic bytes (sorted keys, 2-space indent, LF, trailing newline, ASCII).
3. **`frontend/scripts/gen-contracts.mjs`** (`npm run gen:contracts`) reads those schemas and writes, under `frontend/src/contracts/`, a `<name>.d.ts` (TypeScript types via `json-schema-to-typescript`) plus a byte-copy `<name>.schema.json` that ajv compiles into a runtime validator.
4. **`frontend/src/contracts/index.ts`** is the typed load-boundary: `loadValidated<T>(url, schemaName)` fetches JSON same-origin and validates it with the compiled ajv validator, throwing at the boundary on invalid data (section 1a, "payloads not calls").
5. **The CI `contracts` job** regenerates both sides and fails on any diff (`git diff --exit-code`), so the schema, the types, and the validators can never drift from the models.

A tiny `example` contract (`example.schema.json`) ships as the pipeline's demonstrator and drift-gate exercise; the real named surfaces below are added to the registry in their own rows - Row 7 registered the six core surfaces (`app-config`, `event-envelope`, `save`, `puzzle-file`, `bank-index`, `anagram-puzzle`) plus `copy`, Row 9 the derived layer between the word inventory and the puzzle engine (`derived-wordlists`, `game-wordlist`), the lexicon row the two surfaces (`lexicon`, `lexicon-sources`) that the word inventory now rests on, and row 16 the `served-denylist` that decides what the derived layer refuses to put on a board. The two-runtime context is in [../overview.md](../overview.md).

## Design rationale

- **Pydantic is the single source of truth; JSON Schema, TS types, and validators are generated, never hand-authored.** One model definition yields every downstream artifact, so a field change is made once and the generated types + validators follow. The drift gate makes divergence impossible rather than merely discouraged. (Fowler, user-directed.)
- **Runtime validation is ajv over the generated schema; static types are `json-schema-to-typescript`.** The frontend consumes backend output only as schema-validated payloads and fails fast at the load-boundary. ajv is a runtime dependency (it ships when the boundary is used); `json-schema-to-typescript` is build-time only. (Fowler.)
- **Determinism is engineered, not assumed.** The drift gate runs on CI (Python 3.12, npm 10.9.2) but authors run other versions, so the pipeline pins `pydantic` exactly, canonicalises the JSON (sorted keys, fixed indent), pins `json-schema-to-typescript` and disables its external formatter (`format:false`), and forces LF (`export` `newline`, `.gitattributes`). Same inputs -> byte-identical outputs on every machine.

### Core-surface field decisions (Row 7)

The six core surfaces plus `copy` land as Pydantic models registered in the pipeline. The shape decisions are Fowler's altitude (persisted-contract authority):

- **Per-Game payload schemas, not one mega-schema.** A `puzzle-file` item carries an OPEN `payload` object; each Game validates its own slice against its own schema (`anagram-puzzle` is the first). A new Game costs a payload schema, not an edit to `puzzle-file`, so Games evolve independently. `event-envelope`'s `ctx`/`data` are open for the same reason - pinning them would force a schema bump every time a Game emits a new context key.
- **The save `dayKey` is recomputed on read, never trusted from storage.** It is a derived key (`date|modeId|gameId|packId`); the reader rebuilds it from its value fields so a stale or tampered stored key can never select the wrong day (the guardrails derived-key rule). `compute_day_key` is that single recompute; the read-side migration and the TypeScript twin land with the reader (Row 11).
- **Identifiers are stable slugs; copy is a separate, validated surface.** `gameId`, `modeId`, `packId`, and difficulty are lower-case slugs; player-facing text lives in `config/copy.json`, keyed by a slug. `copy` is a pipeline `SchemaModel` (with `version`/`changelog`) like `app-config`, not a hand-authored map, so there is one source of truth and the drift gate covers it. (Jony + Fowler.)
- **`event-envelope` carries both `v` and `version`/`changelog`.** `v` is the lightweight per-event version a reader uses to evolve its parsing; `version`/`changelog` are the schema-discipline stamp every persisted surface carries (CLAUDE.md section 11). `name` is constrained to the canonical event catalog, so an unregistered name is rejected at the boundary.

### Derived-layer field decisions (Row 9)

The derived layer sits between the word inventory and the puzzle engine: one inventory plus `derived-wordlists` in, one `game-wordlist` per Game out. It selects words; it does not generate puzzles, know what a day is, or write anything into `frontend/public/`. Row 9 cut it from the ranked wordlist the retired corpus ingest produced; the row 12 cutover below re-points it at the published lexicon, and the decisions here are the ones that survived unchanged.

- **The set registry is a schema-backed config, so adding a Game's wordlist is a data change.** `config/derived-wordlists.json` names each set's `gameId`, output path, and selection knobs; `wordsmith/derive.py` is the single mechanism that interprets them. Adding a set is an entry plus a re-run of `rebuild_wordlists` - the same extensibility bargain the source registry makes one layer up, and the reason four more Games (Rows 18-21) cost no framework today. The selection knobs are config rather than Python literals because ezhuthu length ranges and admission thresholds are tunable game-balance numbers (Holy Law #6). Only a predicate the knobs cannot express costs code, which is the same line the lexicon layer draws at an unseen source FORMAT. (Fowler.)
- **`game-wordlist` carries no wall-clock `generatedAt`.** A derived set is a pure function of the inventory it was cut from plus the selection applied, and a timestamp would make two runs emit different bytes - the opposite of what a reproducible build artifact means, and a permanently flapping diff. `source` pins the input by CONTENT instead, and git history records when the file changed (CLAUDE.md section 5). This is what lets a test re-derive the committed artifact and compare it byte for byte, which is also the hand-edit gate. (Fowler.)
- **Whether the tiles spell something else is RECORDED, not required.** Each emitted row carries `anagramFanOut`: how many rows of the SAME served set share its ezhuthu multiset, counting itself, so a solitary word carries 1 and never 0. The earlier `requireCoAnagram` knob made that same question an admission test, and it was wrong twice over. It cost 106 words out of every 107 - the anagram set was 163 rows where the identical selection without it is five figures - and it actively selected for bound stems, because a fragment like a stripped stem is exactly the kind of token that collides with a real word. What the multiset index was measuring is still worth having: a Game that knows a submitted arrangement is a different SERVED word can answer "that is a word, but not today's" instead of a flat rejection, and a player who formed real Tamil and was told they were simply wrong concludes the game cheated. The count is over served rows (after every filter and after the cap) because a partner nobody is served cannot be offered back, and the contract recomputes it on read so a stale count cannot survive. (User + Palm.)
- **`hints` carries only what the data honestly supports.** `firstEzhuthu` and `length` are recomputed from `ezhuthu` on every rebuild and validated against it, so precomputing them cannot drift. The specified `category_ta` is NOT emitted: a Tamil category name is player-facing copy, which lives in `config/copy.json` and never inside a dataset, and only 2,569 of the 162,361 published headwords carry a category at all. The field names are camelCase like every other persisted shape in the repo; the build roadmap's snake_case sketch was normalized in Row 13, while the artifact still had no runtime consumer. (Fowler.)
- **Neither derived-layer schema is registered in `frontend/src/contracts/index.ts`.** Both are build-time surfaces the game never fetches - the browser downloads the puzzles the daily engine bakes (Row 13), not the wordlists they were baked from - so an ajv validator for either would ship dead runtime bytes. Same precedent as `glyph-manifest`; the drift gate still covers them. (Carmack + Fowler.)

### Derived-layer field decisions (row 12 - the cutover to the lexicon)

The derived layer now reads the published lexicon instead of the ranked corpus master. What changed is not the plumbing but what the layer is ALLOWED TO ASK: the corpus could only say where a token ranked, so the committed anagram set served a political party and a sitting politician. The lexicon knows what a word IS.

- **PRESENT and SERVED are different populations, and the ledger is the difference.** `lexiconRows - outsideLength - outsideClass - belowAttestations - belowFrequency - withoutMeaning - capped == rowsKept == len(words)`, enforced by the model - one bucket per serving gate, in the order the identity is read, with a row that fails several charged to the first that stopped it. Removing the old `outsideBand` and `invalidWordFinal` buckets without restating the identity would have left the integrity Oracle with no arithmetic; `masterRows` became `lexiconRows` and counts the lexicon's PUBLISHED rows. What each gate cost is now a number in the committed file rather than a claim in a commit message. (Fowler + Carmack.)
- **`outsideClass` is read off the partition table, not counted line by line.** Selection is an allow-list, so the derived layer opens only the classes it serves and takes the size of the rest from what `lexicon.meta.json` declares about them. That is also why the class gate is evaluated first: a proper noun is not "a word that failed a length check". (Carmack.)
- **The classes a Game may ever serve are a narrowed TYPE, not a config value.** `ServableWordClass` admits `headword` and `colloquial` and nothing else, so `properNoun`, `unclassified`, `notAWord`, `suspectedTypo`, `sandhiArtifact`, `boundStem`, `inflected` and `loanword` cannot reach a player through a one-line config edit. This is the same lesson `PosAlias.wordClassEvidence` taught in Row 3: when a config-driven list routes into a contract enum, check whether the enum admits a value config has no right to assert. Widening it is a reviewed contract change - which is the ceremony the served proper nouns never got. (Fowler + Palm.)
- **The selection knobs carry NO defaults.** A registry entry that forgot to say what it serves must fail to validate rather than quietly serve everything: the defaults ARE the design decision, and a knob landing unset is the failure mode. (Palm.)
- **`minAttestations` has a tier-1 leg, because two bare wordlists agreeing is not evidence.** `minTier1Attestations` requires at least one attestation from a source whose unit is a dictionary ENTRY rather than a string in a list. The spellchecker wordlist alone is several times the size of the largest dictionary and co-occurs with nearly any orthographically legal string, so a plain 2-of-N gate collapses to "one wordlist plus a spellchecker" - and that same membership is already a word-hood signal, so counting it at the gate charges the same evidence twice. The lexicon publishes both counts as integers, so the gate is a direct comparison. (Palm.)
- **`requireValidWordFinal` and its `invalidWordFinal` bucket are deleted.** The rule was the served set's only quality net while word-hood was guessed from orthography; word-final legality is now one of the letter rules the classifier applies before it will call a surface a `headword`, so keeping the knob would apply the same test twice and leave a bucket no row can land under. (Fowler.)
- **`freqBand` is replaced by raw `frequency` plus `frequencyStratum`.** A rank-relative band over a population where thousands of rows occur zero times is a different filter wearing the same name. `frequency` is what `minFrequency` gates on; `frequencyStratum` is which quarter of THIS SERVED SET the row falls in, computed after every gate and after the cap, because a quartile over millions of lexicon surfaces says nothing about the words a player is offered. It is recomputed and re-checked on read, exactly like `anagramFanOut`, so a hand-edited stratum cannot survive. (Palm + Fowler.)
- **`DerivedSource` pins a partitioned input with one digest.** `{metaPath, version, sha256, rows}`, where `sha256` digests `lexicon.meta.json` - which itself carries the sha256 of every published partition, so one hash still fingerprints all 53 files. `generatedAt` went with the master that had one. The derived layer resolves every partition from that document's own table and NEVER globs the published directory: a glob would serve whatever happened to be on disk, including a file the meta document does not vouch for, which is precisely how a class the selection never named would reach a player. A class the lexicon does not publish is a loud error, because a selection that silently serves nothing looks identical to one that works. (Fowler + Carmack.)

### Daily-engine field decisions (Row 13)

The daily engine reads a `game-wordlist` and writes `puzzle-file` days plus a `bank-index`. It is the layer BELOW the derived sets, and it re-derives nothing.

- **`daily-generator` is a separate config surface from `app-config`.** `app-config` is runtime framing the browser ships with (how many items a day holds, which Modes are live); `config/daily-generator.json` holds the knobs that decide how a word becomes a puzzle - attempts, time limit, head start, hint wording and cost, and which ezhuthu lengths at which familiarity are which difficulty. Keeping them apart is the words-versus-engine boundary drawn one layer lower: the engine must be tunable without touching the runtime config the game bundles, and the browser must not download generation knobs it can never use. Adding a second Game's generation is an entry in `games`, not a rewrite of the day loop. (Fowler + Carmack.)
- **A difficulty band bounds TWO axes, and a word no band claims is dropped.** `DifficultyBand` gained `maxStratum` alongside its length bounds in row 12, because length alone is anti-correlated at both tails - see [../../concepts/difficulty-and-scoring.md](../../concepts/difficulty-and-scoring.md) for the argument. `difficulty_of` returns nothing when no band covers a row rather than falling back to the widest one: the wordlist says what is SERVABLE and the bands say what is DRAWABLE, and inventing a difficulty for a row every band refused would put exactly the word on the board that the second axis exists to keep off it. (Carmack + Palm.)
- **A hint's WORDING is config; its TEXT is data.** `HintSpec.template` is a format string over the wordlist row's own honest fields (`{firstEzhuthu}`, `{length}`), so the Tamil lives in `config/`, never in a Python literal, while the rendered per-puzzle string ships inside the payload where a Game can read it. A template naming a field the row does not carry raises rather than rendering an empty hint. How MANY hints a day bakes is `app-config`'s `hints.perGame`, so the switch the shell reads is the switch the generator obeys. (Jony + Fowler.)
- **A baked `puzzle-file` item's payload drops the schema stamp.** The day file carries its own `version` + `changelog`; repeating one inside every item would be bytes a player downloads to learn nothing. The generator still CONSTRUCTS the full `anagram-puzzle` model - that construction is what proves the payload obeys its contract - and strips the two stamp fields on the way out. (Carmack + Fowler.)
- **`save` gained an optional `lastStreakDay`.** A streak ticks once per COMPLETED day, and `lastPlayed` cannot answer "has this day already counted?" because it moves on every write. The field is optional, so a save written before Row 13 still loads and simply has not ticked yet - an additive change with no migration. (Palm + Fowler.)
- **`daily-generator` is not registered in `frontend/src/contracts/index.ts`.** It is a build-time surface; the browser reads the baked bank, never the recipe. Same precedent as the derived schemas. (Carmack.)
- **A published day is frozen; a re-run bakes only what is missing.** A `puzzle-file` is a pure function of its date AND of the wordlist it drew from, so the moment that wordlist changes the committed days stop being re-derivable. Since the daily cron re-runs the generator every night over the whole look-ahead window, an unguarded run would hand a player mid-session a different puzzle for a day they had already started - which is the same class of contract break as a save that no longer loads (CLAUDE.md section 11). `generate()` therefore skips any date whose file already exists, `--rebake` is the deliberate override, and the bank index is rebuilt from disk on every run so skipping can never leave a day unlisted. The consequence accepted with it: the committed bank is history rather than a rebuildable artifact, so the Oracle over it is now "a re-run moves nothing" rather than "a re-run reproduces it". (Fowler + Carmack.)

### Themed-selection field decisions (row 15)

A theme is the Daily's variety mechanism, not a Mode and not a Game: three unrelated anagrams are a list, three that share a theme are a round. It is therefore a SELECTION constraint on the existing generator, and it crosses two contracts - the derived registry that cuts a themed set, and the daily generator that decides which dates run one.

- **`categories` and `pos` are DIMENSIONS, not gates, and the difference is the default.** Both are optional on `DerivedSelection`, and absent means the dimension is not applied. Every other knob is required precisely because a knob landing unset must fail loudly; these two invert that, because the failure mode runs the other way. Only 2,569 of 162,361 published headwords carry any category, so a set that named one by accident would silently collapse from tens of thousands of rows to a few hundred - and how far `pos` reaches over the served set has never been measured. They ship in ONE row rather than two because they are the same mechanism, a set-intersection predicate over a set-valued column, and two rows editing `DerivedSelection` would collide on the drift gate. (Fowler + Palm.)
- **Each dimension gets its own ledger bucket, charged before the gates.** The identity became `lexiconRows - outsideClass - outsideCategories - outsidePos - outsideLength - belowAttestations - belowFrequency - withoutMeaning - capped == rowsKept`. Folding a theme's reach into an existing bucket was the alternative, and it would have made that gate's number a lie - the ledger's whole claim is that every published row is accounted for under exactly one heading. Reading the dimensions first is what makes a themed ledger legible: how far the theme reaches, and then what each gate removed from inside it. Both are 0 on every ordinary set. (Fowler.)
- **A theme is a GROUP of categories, and it must exclude almost everything.** The single categories are tiny - 144 rows for `nature`, 97 for `birds`, 2 for `amphibians`, before any gate - so a single-category Daily lasts days. `themed-nature` unions ten and keeps 429 rows, which is 143 themed days. The floor a theme must clear is excluding 90 percent of the servable set (`themed-nature` excludes 98.7 percent) AND letting a player who knows the theme name five plausible candidates. Without that floor the next person with a large tag ships a "nouns day", which narrows nothing for the player and is a theme in name only. (Palm.)
- **A themed set narrows the ordinary selection and relaxes nothing.** Its gates are byte-identical to the ordinary set's; only the dimension is added. That is what lets a themed day be drawn without asking a second time whether its words were servable - and it means a themed day can never become the back door around a gate. A test asserts the two selections differ only in the dimensions. (Fowler.)
- **`GameGeneration` gained `themes: [{wordlist, copySlug}]`, or the themed set would be a dataset nothing reads.** `build_day` fills a day from `daily.mix` keyed by `gameId`, and each `gameId` maps to exactly ONE `wordlist` path, so no amount of registry editing would have made the day loop open a second file. `load_wordlists` is therefore keyed by the wordlist PATH rather than by `gameId`: a Game now draws from more than one set, and a path is what the registry actually names. (Fowler + Carmack.)
- **A themed day is all-or-nothing, and the day decides it.** A theme runs when it can fill EVERY slot from its own wordlist without repeating a word the bank has served and with every difficulty band it needs non-empty; otherwise the day is ordinary. An ordinary day repeats a served word rather than shipping short, which is the right trade when the alternative is a playlist that does not add up - but a theme has an alternative, so it declines instead. Padding a round with one off-theme word breaks the only promise the round made. (Palm.)
- **`themeEveryNDays` is a knob the plan did not anticipate, added because the measurement moved.** The theme was sized at roughly 111 rows BEFORE the serving gates; it came out at 429 AFTER them, four times the estimate. "Themed whenever a theme can fill the day" would then have made the Daily the same theme every day for about five months, which is the opposite of the variety the theme exists to add. The cadence counts on the date's own proleptic-Gregorian day number, so it is a pure function of the date with no phase knob and no reference to when the bank was first baked; `0` turns themed days off. It sits on `DailyGenerator` rather than inside a theme entry, which keeps a theme entry exactly the two fields it was specified as. (Palm + Fowler.)
- **`puzzle-file` gained an optional `theme`, and it carries the SLUG.** A day that draws every word from one theme must say so or nothing downstream can announce it, and the Tamil label is copy the shell already reads from `config/copy.json` - a baked label would be copy frozen into a build artifact, correctable only by re-baking a day that has already shipped. Absent means an ordinary day, so every day baked before this validates unchanged and the change is additive. A test asserts every registered `copySlug` has copy, because a slug with no string renders as itself, in Latin, on a Tamil stage. (Jony + Fowler.)

### Served deny-list decisions (row 16)

The lexicon knows what a word IS. It cannot know what makes a PUZZLE, and the served set proved it: the 32,310 words the anagram drew from opened with Tamil's grammar - the quotative particle, the demonstratives, the whole pronoun paradigm - and with the personal names and newspaper mastheads a news corpus makes frequent. Because frequency is one axis of difficulty (see [../../concepts/difficulty-and-scoring.md](../../concepts/difficulty-and-scoring.md)), those are exactly the words that land in the EASY band, which is the band a player meets most.

- **The exclusion is a NAMED LIST, not a rule, because the only rule available would have deleted real vocabulary.** A part-of-speech filter was the obvious mechanism and was measured and rejected: `pos` is a UNION across 21 sources, precisely so that one authority's ranking cannot erase another's true fact (Row 3), and that is exactly why it cannot double as a filter - `appa` (father) and `arasu` (government) both carry `interjection`. A list of 72 words a reviewer can argue with is the honest shape for a judgement no column carries, and its collateral damage is visible in the diff rather than discovered by a player. The 27 words reviewed alongside it and deliberately KEPT are recorded in the file's own `note`, so the next contributor cannot re-derive the rejected rule by feel. (Palm + Fowler, user-directed.)
- **`reason` is required on every entry and is never rendered.** It is written for the reviewer deciding whether the NEXT proposed entry belongs, which is the only thing standing between a curated list and a list that grows by feel. Where a denied word carries a real dictionary sense that is not what its frequency counts - `kumaar` is listed as "prince" and occurs 329,467 times because it is a surname - the reason says so, so nobody re-adds it as vocabulary that was wrongly cut. (Fowler.)
- **Two arrays, not one, because the two judgements age differently.** A function word is off the board because it is grammar rather than vocabulary, and that is stable for the life of the language. A proper noun is off the board because a corpus made a name frequent, and that follows whichever corpora are staged. A reviewer needs to know which argument an entry is making before deciding whether it still holds. (Palm.)
- **The match is WHOLE-WORD, and the exclusion is on SERVING only.** A prefix or substring match over an agglutinative language would take dozens of real words per entry. And every denied word stays in the published lexicon at `datasets/lexicon/`: it is real Tamil, it is attested, and a dictionary lookup, a frequency study or a future Game where the player RECOGNISES rather than produces a spelling must not lose the row. A deny-list that edited the inventory would be the destructive funnel the lexicon layer exists to remove. (Fowler + Carmack.)
- **`denylistPath` hangs off the REGISTRY, not off a set.** What makes a word unservable is true of every Game, so a per-set deny-list would let the next registered set opt out of it by omission - the same failure the class allow-list was narrowed to a type to prevent. It is required and has no default, because an absent deny-list and an empty one produce identical output and the one this layer exists to prevent is the absent one. It is a path in config rather than a Python literal on the same terms as `lexiconPath` (Holy Law #6). (Fowler.)
- **`denylisted` is charged LAST of the row-level buckets, after every automatic gate and before the cap.** The identity became `lexiconRows - outsideClass - outsideCategories - outsidePos - outsideLength - belowAttestations - belowFrequency - withoutMeaning - denylisted - capped == rowsKept`. Charging it FIRST was the alternative and it reads as the stronger statement - "this word is never served, full stop" - but it would have made the bucket count words that were already off the board for a reason of their own. Last, the number is a MEASUREMENT of the curation: how many words the list ALONE keeps off, which is what says whether an entry still earns its line. On the committed sets that is 72 of 72 for the anagram and 0 for `themed-nature`, because no denied word carries a nature category. (Fowler + Carmack.)\n\n### Lexicon-layer field decisions (Row 3)

### Lexicon-layer contract decisions (Row 3 - contracts before logic)

The lexicon replaces the corpus layer's destructive funnel: every surface any source showed us keeps a row and every fact a source asserted. The vocabulary - what a `wordClass` is, attestation versus observation, why `length` counts ezhuthu - is defined once in [../../concepts/lexicon.md](../../concepts/lexicon.md); what follows is why the CONTRACT has the shape it does.

- **TWO contracts, and the row shape is deliberately not a `SchemaModel`.** The artifact is streamed NDJSON with a sibling header, so `Lexicon` is the META document (`version`, `changelog`, `provenance`, `counters`, the partition table) and `LexiconEntry` is the row. `base.py` forces `version` + `changelog` onto every `SchemaModel`, which is exactly what a data row must not carry - repeating a schema stamp on millions of lines is bytes a reader learns nothing from. So `LexiconEntry` is a plain model and is absent from the registry, and `Lexicon` holds an optional `rowSchema` reference to it purely so Pydantic emits it into `lexicon.schema.json`'s `$defs`. Without that reference the row shape would ship with no schema at all, which is a Holy Law #3 break the drift gate cannot see. (Fowler.)
- **The meta document carries no `words` list, and the counters are the Oracle.** The lexicon is streamed with no in-memory row list, so the reconciliation reads `counters.published.rows` and the partition table's declared counts rather than `len(words)`. `byClass` carries a bucket for EVERY `wordClass` - a missing bucket and a zero bucket say different things and only one of them is a measurement - the buckets sum to their census's `rows`, and the partitions declare the same population class by class. Move one class count and the document stops validating, which is what proves the layer's thesis: nothing is discarded. This is the same integrity ledger `game-wordlist` carries, adapted to a set nobody can hold in memory. (Fowler.)
- **No `generatedAt`.** Identity is content-addressed through `provenance[].sha256` plus the row count, so a rebuild byte-compares and a hand-edit is detectable; git records when. This is not symmetry with the retired corpus layer's ranked wordlist - it is a correction of it, since that artifact filled `generatedAt` from a wall clock and was therefore already not byte-comparable, and the defect leaked into every derived set through `DerivedSource.generatedAt`. (Fowler.)
- **Every sparse column is OPTIONAL and never a defaulted empty list.** `model_dump(exclude_none=True)` drops `None` but keeps `[]`, so a defaulted empty list writes an empty pair on every row that lacks the fact - roughly 200 MB of nothing across the published set. `min_length=1` makes "absent" the only way to say "no value". (Fowler + user.)
- **Two columns are omitted from the published rows, under a stated principle rather than case by case.** `wordhood` and `freqRank` are omitted because BOTH hold: each is a DERIVED DIAGNOSTIC of this pipeline rather than a fact a source asserted, AND omitting it cannot cost the project the fact - `freqRank` is recomputable from the published `frequency`, and `wordClass` IS `wordhood`'s verdict. The test is deliberately "recomputable from the COMMITTED ARTIFACT", not "from the sources": `frequency` is recomputable from the frequency sources, so a source-based test would re-permit dropping it. The contract still types both, because the build-time store carries them and an untyped diagnostic is an untyped diagnostic. (Carmack + Fowler.)
- **`wordhood` is a NAME-KEYED MAP, not a fixed-arity object.** Signals arrive in separate rows of work, and a fixed struct would force whichever row lands first to ship a half-populated object. The keys are a closed enum, so a misspelled signal name is rejected rather than silently minted. (Fowler.)
- **`pos` UNIONS while the English translation RESOLVES, and the difference is not arbitrary.** A translation occupies ONE display slot, so one source must win and precedence decides it. `pos` is a set-valued fact with no slot - a Tamil verbal noun is genuinely both a noun and a verb, and a word can be a noun in one authority and a verb in another - so resolving by precedence would DELETE a true fact because of a ranking that exists for a different purpose. The same reasoning is why the collapsed `gloss` field was split into three named ones: a field name that states neither its language nor its kind is how three different facts with three different consumers came to share one slot. (Fowler.)
- **The `pos` VOCABULARY is contract; the raw-tag MAPPING is config.** Parts of speech are a fact about the language, not a tunable knob, so the enum is closed - the same category as `wordClass` and the word-final mei table. An open vocabulary buys a data-only edit for a set that changes roughly never and pays for it by removing the only thing that catches `Nouns` versus `noun` versus `nouns`. Its members are fixed by a full census over every row of the acquired sources, never guessed from a sample, and every member has a producer on disk. What IS config is `posAliases`: which raw source tag lands where. A raw tag with no entry is a hard publish failure naming the tag and its row count - never dropped, which is the defect this layer exists to remove, and never passed through, which would defeat the closed enum. (Fowler.)
- **`properNoun` is a `wordClass`, never a `pos`, and the alias map has three destinations because the census has three kinds of tag.** One fact, one home. But a census over real dictionaries does not yield parts of speech alone: `name` is word-class evidence, `prefix` and `suffix` are bound morphemes, `proverb` and `phrase` are multi-word units, and a structured POS field can carry a recurring value that names no part of speech at all. A row with no POS value is NOT that last case - it is a counted parse reject at extract, where the stage's own ledger already accounts for it, because failing fast at the boundary means extract rather than publish three stages later. So an alias routes a tag to `pos`, to `wordClassEvidence`, or to a named `reject` - and a tag may route to both of the first two, because `noun plural` carries two facts and each goes to its own home. `wordClassEvidence` is a NARROWER enum than `wordClass`: `posAliases` is config, so on the wider type a one-line edit would let a non-authority source assert word-hood, and `unclassified` is a non-verdict nothing can be evidence FOR. Evidence is the classifier's INPUT, never its verdict, and the type is what enforces it. A tag with no destination at all is rejected by the model. (Fowler.)
- **Tamil has POSTpositions, so the enum carries `postposition` and not `preposition`.** The English-to-Tamil dictionary's part-of-speech prefix describes its ENGLISH headword, and its `preposition` rows translate to Tamil's own adposition, which is postpositional. Mirroring the source label would put into a contract that claims to describe Tamil a category the language does not have. Where there is no Tamil counterpart AT ALL - `article`, and a lone `relative` sense of English "but" - the tag is registered with an explicit rejection reason instead of being bent onto the nearest member, on the same terms that kept an invented Tamil category name out of the derived sets: a mapping that asserts more than the data knows is worse than an absent value. (Fowler.)
- **Three provenance fields, and one of them is REQUIRED. SUPERSEDED - none of the three exists.** Row 11 dropped `meaningSource`, `translationEnSource` and `categorySource` (see the Row 11 section below), and Row 14 deleted the `ProvenanceState` vocabulary they were typed by. The entry is kept because the REASONING still binds anything that tries to reintroduce them, and because the rule that later rode on it - never SELL an unreviewed authored value as a paid hint - was withdrawn on 2026-08-17 once measured: 1,210 of 32,310 servable words (3.7 percent) would show an authored meaning, and reading them they are accurate Tamil, so the rule guarded a slice that did not need guarding. What survives unchanged is the last sentence: none of it is ever rendered to a player, because an "AI-written" badge on some meanings makes a player distrust all of them. The original reasoning follows. `meaningSource` covered `definitionTa` and `synonymsTa` as ONE reviewable unit, because they compete for one display slot. `translationEnSource` was the plain source id that won. `categorySource` was required wherever `categories` is present, because a category renders as a PAID hint: a wrong meaning on a summary screen is embarrassing, but a wrong category the player paid an attempt for and then reasoned from is the game lying and charging for it. (Palm + Fowler.)
- **`spokenRatio` and `compound` are published as SIGNALS, never as gates.** Summing frequency across sources destroys the per-source split, and that split is the best familiarity signal in the inventory - a word frequent in subtitles and rare in news is everyday spoken Tamil. `spokenRatio` is what survives of it, at zero authoring cost from data already on disk. `compound` makes measurable the claim that long headwords are mostly compounds and therefore easier - a claim a whole difficulty curve currently rests on. Sandhi makes it noisy, which is exactly why it is a signal and not a filter, the same status `anagramFanOut` holds. (Palm.)
  - **MEASURED 2026-08-17, and the claim above did not survive it.** `spokenRatio` is **0.0 on 91.9 percent of served rows**, so it separates almost nothing: the declared spoken corpora are far too small a share of the summed frequency for the ratio to be informative on most words. It cost nothing to carry and it earns nothing either. Before any selection or difficulty rule is built on it, it needs a second spoken-register source - subtitles, transcribed speech - or it should be DROPPED. Recorded here rather than acted on, because deleting a published column is a contract change and no reader depends on it today. `compound` was never published at all, so the claim it was meant to make measurable remains unmeasured.
- **`freqBand` is not carried forward.** A rank-relative band over a population where thousands of rows have `frequency == 0` is a different filter wearing the same name, and keeping the name would make a design decision look like a rename. Raw `frequency` plus an absolute floor at selection time replaces it. (Palm.)
- **`elementKind` is REQUIRED on a `json-array` source, forbidden elsewhere, and has no default.** It names which element grammar the array holds, and the two members are exactly the two grammars a streaming reader can decode safely - the SELF-TERMINATING rule, defined once in [../lexicon/pipeline.md](../lexicon/pipeline.md#the-self-terminating-element-rule). Two acquired sources hold bare string elements, so the contract WIDENS rather than relaxes. A default would be exactly the silent assumption the rule exists to prevent. Following the same fail-fast precedent the corpus registry set, a mapping set on the wrong kind is REJECTED rather than ignored - including `hasHeader`, whose non-null default let it slip through that check in the corpus contract. (Fowler.)
- **`rootKey` is OPTIONAL on a `json-array` source, and its absence is an assertion.** It names the key the array hangs under; omitted, it says the document ROOT is the array - which one acquired source, 56,856 elements inside a bare top-level `[`, actually is. The reader checks the claim against the bytes and raises when the root is something else, so the absence is never a fallback it guesses. The initial mint required the key, which no source on disk could satisfy; it is corrected here rather than worked around, because a registry that cannot describe a real source is the contract failing at its one job. (Fowler.)
- **`pageNamespace` is REQUIRED on a `mediawiki-xml` source, forbidden elsewhere, and has no default.** A wiki export interleaves articles with talk pages, templates, categories and project discussion, so which pages are this source's RECORDS is a fact about the export rather than about the format - the same thing `hasHeader` says about a delimited file's first line, and declared the same way. A default of `0` would be a guess about somebody else's dump. Every field mapping is rejected on this kind: the record IS the page, so the reader knows the export's own element names and a `wordField` on it would be a knob that silently does nothing. The knob is not cosmetic - it is what lets the reader decline to accumulate an out-of-namespace page's text, which is what keeps peak memory proportional to the largest ARTICLE rather than to the largest PAGE, a factor of forty-five on the Tamil Wiktionary dump. (Fowler + Carmack.)
- **`sources` does not survive; `attestedBy` replaces it.** Which scraper OBSERVED a surface decides nothing about word-hood and stays in the build-time store; only authorities that carried a headword fact reach the published row. (Fowler + user.)
- **Neither lexicon schema is registered in `frontend/src/contracts/index.ts`.** Both are build-time surfaces the browser never fetches, so an ajv validator for either would ship dead runtime bytes. Same precedent as the derived schemas and `glyph-manifest`; the drift gate still covers them. (Carmack + Fowler.)
- **Migration class is build-time rewrite-in-place.** A change stamps `version` and appends a `changelog` entry and needs no read-side migration, because the only reader is `backend/` and every artifact regenerates in the same commit. (Fowler, CLAUDE.md section 11.)

### Lexicon-layer field decisions (Row 11 - the first writer)

Row 3 wrote the contract before anything read or wrote it, which is Holy Law #3 working as intended: the shape was reasoned from the source census rather than from an artifact. Row 11 is the first stage that actually WRITES one, and several of those decisions did not survive contact. Each is corrected here rather than left standing beside its replacement.

- **`counters` splits into `classified` and `published`, and publication is ALL-OR-NOTHING per class.** The publish policy commits four servable classes of ten, so a single counter would have made the six withheld ones unprovable - the artifact would have counted what it carried and said nothing about what it did not. `classified` is a census of the whole population the store holds; `published` counts the files. The model enforces that a published count is either zero or exactly the classified count, so a partial count is rows LOST between the classifier and the writer rather than rows withheld - the one failure a per-class policy would otherwise hide. (Fowler.)
- **The partition address is `["wordClass", "baseEzhuthu"]`, declared in the artifact.** `length` leaves the partition table: it addressed nothing, and a partition key that is sometimes absent is worse than one that is always there. Both surviving keys are immutable per word, so a refresh INSERTS into a file and only a re-classification moves a row. `partitionKeys` is pinned by the model, so a document declaring an address the writer does not use cannot validate - a declared address nothing enforces is a comment wearing a field's clothes. `ezhuthuIndex` decodes each hex key ONCE to `{ezhuthu, roman, kind}`, which is where the Tamil letter and its ASCII spelling live: correctable DATA in a document a reviewer already opens, never a path component a correction would rename. Row 11 addressed the WHOLE opening ezhuthu and Row 12a narrowed it to the BASE letter - see below. The layout argument itself is [../lexicon/pipeline.md](../lexicon/pipeline.md). (Carmack.)
- **The row is cut to facts and counts: `attestedBy`, the three `*Source` stamps, `compound` and `ezhuthu` all go.** `attestedBy` put a list of source slugs on every row so that selection could take its length, so it publishes as `attestations` plus `tier1Attestations` - two integers, because a boolean tier flag costs the same bytes on the line and says strictly less, and the pair gives the contract a checkable invariant besides. The `*Source` stamps and `compound` had no reader: `translationEnSource` and `categorySource` traced a provenance nothing traced FROM, `meaningSource` would read `attested` on nearly every row now that Tamil-definition sources exist, and `compound` was never set by anything. Provenance answers a question about ONE word, and the store is what answers that. `ezhuthu` goes for the reason `freqRank` always was going to: it is `segment(word)`, a pure function of a published column, so a stored copy is a DRIFT SURFACE as well as 66.5 B a row - and `length` now validates against the LIVE segmentation, which keeps the whole guarantee at a fortieth of the cost. (Fowler + user.)
- **`LexiconProvenance.rowsIn` / `factsOut` become `observations` / `facts`.** No stage retains a raw input row count once the extract is written, so a field called `rowsIn` could only ever have been filled with one of the two things the store CAN prove, wearing the wrong name. (Fowler.)
- **`lexicon-sources` gains three PUBLISH knobs.** `publishedClasses` (which classes are committed), `spokenSources` (which frequency corpora are spoken Tamil) and `maxPartitionBytes` (the file-size assertion). All three are knobs, so Holy Law #6 puts them in config beside `lexiconRoot` and `outputs`. `spokenSources` MAY BE EMPTY, and that is a real state rather than a degenerate one: it says this registry names no spoken corpus, and then no row carries a spoken share at all - where a zero would say "never spoken", a different and false claim. Naming the spoken corpora in one place beats tagging every frequency source `written`, which would be this list's complement restated ten times. (Fowler + Palm.)

### Lexicon-layer corrections (Row 12a - the first refresh)

Row 11 was the first writer; Row 12a is the first REFRESH, and three of Row 11's shapes did not survive a reader looking at the bytes.

- **`definitionTa` becomes a LIST of senses.** It was resolved as a single display slot by precedence, which is right for `translationEn` and wrong for a meaning: a Tamil Wiktionary page lists every sense of its word under one meaning block, and the slot published the first. Measured over the extract, 58,193 of the 234,853 pages that assert a sense assert more than one, and 115,545 senses were being discarded at the last stage of the pipeline. The column is now an ORDERED UNION under exactly the rule that used to pick the winner, so element zero is still what a hint spends and nothing is thrown away. It is the ONE list the contract does not sort, because order is information here - sorting would put whichever sense begins with the earliest code point in front of a player - and distinctness is enforced instead. (Fowler + user.)
- **The row serializes in the CONTRACT's field order, human-first.** `sort_keys=True` opened every row on `attestations` and buried `word` eight fields in. Pydantic returns fields in declaration order, so the declaration IS the serialized order and a test pins the list; that is exactly as deterministic as a sort, which is what the byte-identity Oracle needs. `attestations` and `tier1Attestations` move LAST rather than out: Row 12's serving gate is their only consumer and it runs against the published artifact, so they have to be on the line and nobody reads them by eye. (User.)
- **`firstEzhuthu` becomes `baseEzhuthu`, and the key is always four hex digits.** Addressing the whole opening ezhuthu split one letter across up to thirteen files - 115 for the `headword` class alone - and no consumer wants `ka` without `kaa`. The base letter is the unit a dictionary files a word under, it is one code point by construction, and the fixed width is what makes filename order equal code-point order. It also retires an assertion: a decomposed letter carries the same base code point as a composed one, so the NFC check the old address needed has nothing left to refuse. (Carmack + user.)
- **`SourceRole` gains `encyclopedic`.** A Tamil Wikipedia title list asserts neither word-hood nor a count, and none of the five existing roles was true of it; filing it as an `authority` would have emitted a `headword` fact per title and added one to the `attestations` count the serving gate reads, for every place name in Tamil Nadu. `attestationTier` stays forbidden on it, so it can never make a surface a word. What the source can and cannot settle is measured in [../lexicon/word-hood.md](../lexicon/word-hood.md). (Fowler.)

### Word-hood config decisions (Rows 7, 8 and 9)

`config/wordhood.json` is what the lexicon's ENRICH stage reads. WHAT the signals are and what each catches is [../lexicon/word-hood.md](../lexicon/word-hood.md); what follows is why the CONTRACT has the shape it does.

- **The knobs are a schema-backed config because they are a persisted surface.** CLAUDE.md section 11 names config as one of the surfaces every schema rule covers, and Holy Law #6 is what puts these numbers in a file rather than in Python - which is exactly what makes the file need a schema. The alternative considered and rejected was leaving it a plain hand-validated JSON: a hand-edited weight that no model checks is a silent behaviour change over 6.25M rows, and it would be the only config in the repo outside the drift gate. (Fowler, Holy Laws #3 and #6.)
- **Weights are validated to fit inside the score they are subtracted from, and a configuration that overruns is REJECTED rather than clamped.** Clamping flattens every defective surface onto zero, and then no threshold downstream can tell an unopenable surface from a merely mis-ended one - which is the entire reason the signal is a score and not a bit. (Fowler.)
- **Each source list requires at least one entry.** A membership signal whose list is empty is a column of zeros wearing a name, and a column of zeros is indistinguishable from a signal that honestly found nothing. Same reasoning that kept an always-absent `pos` field out of the corpus layer: a field with no producer asserts nothing and hides that it asserts nothing. The complementary check - that a named id is actually STAGED - cannot live in the contract, because the contract does not see the store; it is a fail-fast check at the start of the ENRICH run. (Fowler.)
- **The letter rules are NOT in this file.** Which ezhuthu may open a Tamil word, which eight may end it, and which mei clusters are legal are facts about the language, in the same category as the `wordClass` set and the part-of-speech vocabulary - so they live in the ezhuthu library and are tested exhaustively over the 247-ezhuthu inventory. Only what a broken rule COSTS is a knob. (User + Fowler.)
- **`wordhood` is not registered in `frontend/src/contracts/index.ts`.** It is a build-time surface the browser never fetches; an ajv validator for it would ship dead runtime bytes. Same precedent as the derived and lexicon schemas and `glyph-manifest`; the drift gate still covers it. (Carmack + Fowler.)
- **One bound in this schema is about COST rather than correctness, and it is stated anyway.** `maxEditDistance` is capped at 2. A 3 would validate fine as a number and describe a perfectly correct search - it would just take hours instead of minutes and build an index two and a half times the size. Raising it is therefore not a tuning decision but a contract change, which is exactly what a schema bound makes it. The pipeline asserts the same number again before it builds anything, because a bound stated in only one of the two places is a bound someone can construct their way around. (Carmack + Fowler.)
- **`evidencePriority` must be a PERMUTATION of the evidence vocabulary, and a partial list is rejected.** It decides which class wins when two sources assert different ones, so an unranked value has no defined winner and the verdict would fall back on whatever order SQLite returned the facts in. A validator that accepted a partial list would let a config edit make the classifier non-deterministic without changing a line of code. (Fowler.)
- **`entryAttrs` was retired, and what replaced it is a field on the SOURCE.** The knob named which describing attribute made an attestation an ENTRY, asked per row. Measured, that punished the largest curated dictionary for one unusable column - it emits no `pos` at all, because its blanket `nouns` stamp was rejected at extract, so 82.6 percent of its 104,073 headwords were demoted. What a source's unit IS cannot be recovered from one row of it, so `attestationTier` (`lexicographic` / `enumerative`) is declared on the source in `lexicon-sources`, required exactly on the roles that may assert word-hood and forbidden on the rest - the same shape `elementKind` follows. A knob with no reader left is a lie in the config, so it went rather than lingering as documentation. (Row 9a, Holy Law #6.)
- **`notAWord` is a member of the closed `WordClass` set, not a flag and not a merge into `unclassified`.** It is a CONFIDENT NEGATIVE about the string; `unclassified` is an ABSENT verdict. Both are unservable, so merging them would cost a player nothing and cost the layer its only two honest counters - how much junk came in, and how much real work is left. Additive to the enum, so every existing row still validates, and the three thresholds behind it live in `wordhood` under `classifier.notAWord` rather than as Python literals. (Fowler, Row 9a.)
- **The discovery floor and the typo ceiling are separate knobs even where they share a value.** Both sit at the measured n-gram separator today, but they answer different questions - "probable enough to be a word we missed" and "improbable enough to be a slip" - and one knob would mean tuning either silently moved the other. (Fowler.)

| A part-of-speech filter instead of the served deny-list | Measured and rejected: `pos` is a UNION across 21 sources by design, so `appa` (father) and `arasu` (government) both carry `interjection` and the rule would have deleted real vocabulary. The union is correct - it stops one authority's ranking erasing another's true fact - which is exactly why it cannot double as a filter. A named list of 69 words shows its collateral damage in the diff. | Palm + Fowler (user-directed) |
| Deleting the denied words from the lexicon instead of from the served set | They are real Tamil, attested, and carry dictionary senses; a deny-list that edited the inventory would be the destructive funnel the lexicon layer exists to remove, and a frequency study or a future recognise-rather-than-produce Game would lose the rows. The exclusion is on SERVING only. | Fowler + Carmack |
| A per-set deny-list inside each `sets[]` entry | What makes a word unservable is true of every Game, so a per-set list would let the next registered set opt out of it by omission - the same failure the class allow-list was narrowed to a TYPE to prevent. `denylistPath` sits on the registry. | Fowler |
| Charging `denylisted` FIRST, before the automatic gates | It reads as the stronger statement, but the bucket would then count words that were already off the board for a reason of their own, and the number would say nothing about how much curation the set needed. Charged last, it measures what the list ALONE removed. | Fowler |
| Matching deny-list entries by prefix or stem | Tamil agglutinates, so a stem match would take dozens of real words per entry - the same class of invisible collateral damage as the part-of-speech rule. The match is whole-word and exact. | Carmack |
| A hand-authored `config/copy.json` map with no schema | A second, un-validated surface that drifts from the pipeline; `copy` is a `SchemaModel`, so the drift gate and ajv cover it like every other contract. | Fowler |
